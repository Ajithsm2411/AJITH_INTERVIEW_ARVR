Chapter 1: Introduction 1.1 Project Overview & Motivation

1. INTRODUCTION

1.1 Project Overview & Motivation

The rapid globalization of high-technology enterprises, paired with the proliferation of distributed engineering teams, has placed remote hiring at the critical core of modern organizational growth. However, conventional telecommunication platforms—predominantly two-dimensional video conferencing applications such as Zoom, Microsoft Teams, and Google Meet—suffer from inherent structural deficits that severely degrade the quality of executive and senior technical evaluations.

Foremost among these shortcomings is the total collapse of mutual gaze and natural eye contact. Because video conference cameras are physically separated from display monitors by substantial vertical and horizontal offsets, candidates and evaluators can never look directly into one another's eyes. When a participant looks at the camera to simulate eye contact, they lose visual connection with the other person's micro-expressions; conversely, when focusing on the display, they appear disengaged or looking downward. This phenomenon, known in human-computer interaction as the "parallax gaze disparity," triggers subconscious conversational friction, increases cognitive fatigue, and obscures authentic non-verbal behavioral cues.

The Spatial Computing Paradigm Shift: By projecting participants into an immersive, shared 3D virtual environment with 6 Degrees of Freedom (6-DoF) tracking, MetaSphere VR restores authentic physical co-presence. Evaluators and candidates sit exactly 1.3 meters apart across an executive conference table, sharing identical sightlines, natural acoustic attenuation, and interactive digital artifacts.

MetaSphere VR Interview Telepresence Platform was conceptualized and developed to solve this fundamental challenge. Engineered using a hybrid architecture encompassing Unity Universal Render Pipeline (URP), OpenXR, WebXR Device APIs, and ASP.NET Core Kestrel WebSockets, the platform synthesizes an executive corporate boardroom in real time. It enables bidirectional telepresence between an Interviewer and a Candidate, supporting:

  • True Face-to-Face Spatial Alignment: Physical eye-level positioning at 1.22 meters with exact 1.3-meter separation distance across a mahogany conference table.
  • Dynamic Perspective Switching: Instant seat transitions between Interviewer Chair (facing candidate at 180° yaw) and Candidate Chair (facing interviewer at 0° yaw).
  • Zero-Clip Avatar Head Culling: Automatic mathematical suppression of the local user's own avatar head mesh to prevent near-clipping occlusion while preserving external visual fidelity.
  • In-Situ Evaluation Rubrics & Live Telemetry: Seamless spatial display of candidate dossiers, real-time audio VU meters, and automated recruitment scorecards.

Chapter 1: Introduction 1.2 Problem Statement & Remote Challenges

1.2 Problem Statement & Challenges in Remote Executive Evaluation

Evaluating senior leadership, systems architects, and executive personnel requires qualitative assessments that extend far beyond verbal answers. Evaluators must gauge communication composure under pressure, clarity of architectural thought, low-latency problem-solving instincts, and authentic interpersonal presence. In traditional 2D remote settings, multiple technical and psychological barriers undermine these objectives:

1. Cognitive Overload & "Zoom Fatigue" Staring continuously at 2D monitor grids without spatial depth causes severe neurological strain. The human brain continuously exerts subconscious energy attempting to interpret unnatural 2D visual cues.
2. Parallax Gaze & Disjointed Geometry Camera-screen physical offset destroys natural eye lines. Interviewers cannot discern whether candidate eye shifts indicate technical contemplation or reading offscreen cheat-sheets.
3. Evaluation UI Clutter & Context Switching Interviewers juggle multiple windows: resume PDFs, evaluation rubrics, scoring spreadsheets, and video windows. Switching context pulls attention away from candidate engagement.
4. Asymmetric Cross-Platform Hardware Participants utilize diverse client platforms ranging from dedicated standalone VR headsets (Meta Quest 3) to standard desktop browsers without VR hardware available.

Formal Problem Definition

The engineering problem addressed by this project is formally stated as follows:

"To design, implement, and validate an enterprise-grade, low-latency spatial telepresence platform capable of delivering bidirectional face-to-face interaction across heterogeneous VR headsets and web browser clients, satisfying motion-to-photon latency \(T_{\text{MTP}} < 12\,\text{ms}\), network round-trip time \(T_{\text{RTT}} < 50\,\text{ms}\), frame rates \(\ge 90\,\text{Hz}\), while natively integrating candidate dossiers and synchronized evaluation rubrics directly within the 3D perceptual field."

Meeting this objective demands overcoming tight algorithmic bottlenecks: decoupling high-frequency sensor reading loops from rendering pipelines, developing predictive pose extrapolation models, and engineering zero-copy network serialization protocols.

Chapter 2: Domain Knowledge & Acquisition 2.1 Spatial Computing & 6-DoF Kinematics

2. DOMAIN KNOWLEDGE & ACQUISITION

2.1 Spatial Computing Foundations & 6-DoF Kinematic Mathematics

Spatial computing merges digital artifacts into physical three-dimensional space, requiring rigorous kinematic mathematical formulations. Unlike conventional 3-DoF systems that only measure rotational orientation (Roll, Pitch, Yaw), modern telepresence demands full 6 Degrees of Freedom (6-DoF), encompassing both rotational orientation and three-dimensional translational position:

The 6-DoF Kinematic State Vector: $$\mathbf{X}(t) = \begin{bmatrix} \vec{P}(t) \\ \mathbf{q}(t) \end{bmatrix} = \begin{bmatrix} x(t), & y(t), & z(t), & q_x(t), & q_y(t), & q_z(t), & q_w(t) \end{bmatrix}^T$$ Where \(\vec{P}(t) \in \mathbb{R}^3\) represents spatial position relative to the boardroom world origin, and \(\mathbf{q}(t) \in \mathbb{H}\) represents a unit quaternion satisfying \(\|\mathbf{q}\| = \sqrt{q_x^2 + q_y^2 + q_z^2 + q_w^2} = 1\).

To prevent gimbal lock—a catastrophic loss of rotational freedom inherent in Euler angles when pitch approaches \(\pm 90^\circ\)—all spatial orientations within the MetaSphere engine are computed using unit quaternions. The transformation matrix \(\mathbf{M}_{\text{world}} \in \mathbb{R}^{4 \times 4}\) mapping local avatar head coordinates to world space is computed as:

\(\mathbf{M} = \begin{bmatrix} 1 - 2(q_y^2 + q_z^2) & 2(q_x q_y - q_z q_w) & 2(q_x q_z + q_y q_w) & P_x \\ 2(q_x q_y + q_z q_w) & 1 - 2(q_x^2 + q_z^2) & 2(q_y q_z - q_x q_w) & P_y \\ 2(q_x q_z - q_y q_w) & 2(q_y q_z + q_x q_w) & 1 - 2(q_x^2 + q_y^2) & P_z \\ 0 & 0 & 0 & 1 \end{bmatrix}\)

Predictive Pose Extrapolation Algorithm

Because network transmission introduces round-trip delay, rendering received poses directly would result in perceptible jitter and visual lag. To maintain smooth 90Hz animation, the engine implements a continuous second-order Taylor predictive pose extrapolator:

\(\vec{P}_{\text{pred}}(t + \Delta t) = \vec{P}(t) + \vec{V}(t)\Delta t + \frac{1}{2}\vec{A}(t)\Delta t^2\)

Where \(\vec{V}(t)\) and \(\vec{A}(t)\) represent estimated instantaneous linear velocity and acceleration vectors, and rotational orientation is interpolated using Spherical Linear Interpolation (Slerp):

\(\mathbf{q}_{\text{pred}}(t + \Delta t) = \text{Slerp}(\mathbf{q}(t), \mathbf{q}_{\text{target}}, \alpha) = \frac{\sin((1-\alpha)\theta)}{\sin\theta}\mathbf{q}(t) + \frac{\sin(\alpha\theta)}{\sin\theta}\mathbf{q}_{\text{target}}\)

Chapter 2: Domain Knowledge & Acquisition 2.3 Telepresence & Audio Viseme Synthesis

2.3 Real-Time Network Telepresence, Latency SLAs & Audio Viseme Synthesis

The psychological sense of "telepresence"—the subjective feeling of physically existing in the same room with another human being—is exquisitely sensitive to latency disparities between visual motion and auditory speech. Cognitive neuroscience studies demonstrate that when visual mouth motion lags audio speech by more than 45 milliseconds, conversational rapport degrades rapidly.

1. Motion-to-Photon SLA (\(\le 12\,\text{ms}\)) The duration between physical head movement and the display of newly rendered photons on the OLED/LCD panels. Exceeding 20ms induces vestibulocochlear dissonance and simulator sickness.
2. Audio-Visual Viseme Sync (\(\le 30\,\text{ms}\)) Synchronizing jaw translation and mouth mesh blendshapes with spoken phonemes. Achieved via deterministic NTP timestamp tagging on all outbound WebSocket packets.

Real-Time Audio Viseme Generation Pipeline

In traditional high-budget volumetric systems, facial tracking relies on multi-camera depth sensors. For universal telepresence, MetaSphere VR acquires an acoustic-to-viseme extraction pipeline powered by the browser's Web Audio API AnalyserNode:

  1. Microphone Stream Acquisition: Captures uncompressed PCM audio via navigator.mediaDevices.getUserMedia().
  2. Fast Fourier Transform (FFT): Computes frequency power spectrum over 2048 samples using a Hann window at 60Hz.
  3. Root Mean Square (RMS) Extraction: Determines instantaneous voice energy \(E_{\text{RMS}} = \sqrt{\frac{1}{N}\sum_{i=0}^{N-1} x_i^2}\).
  4. Dynamic Decibel Normalization: Normalizes audio levels to decibels: \(\text{dB} = 20 \log_{10}(E_{\text{RMS}})\), mapped smoothly onto \([0.0, 1.0]\).
  5. Blendshape Modulation: Drives the 3D avatar's mouth mesh vertical scale \(S_y = 1.0 + 1.2 \cdot \text{Level}_{\text{norm}}\) and updates the spatial VU meter fill bar in real time.
Speech-to-Text Transcription Bridge: Concurrently, spoken words are fed through the continuous SpeechRecognition engine, transcribing spoken answers into floating 3D text dialogues directly visible above the candidate's avatar.

Chapter 3: System Design 3.4 Module Design & Decomposition

3.4 Module Design & Architectural Deconstruction

The software architecture is engineered following a modular, loosely coupled paradigm. By separating responsibilities into distinct subsystems, the platform achieves robust maintainability, enabling independent updates to rendering shaders without perturbing networking protocols or evaluation databases:

Module 1: Spatial Kinematics & Rig Controller Component: VRGogglesRig.cs & engine.js
Interfaces with OpenXR / WebXR hardware runtimes. Handles 6-DoF tracking, mouse simulation fallbacks, controller laser raycasting, and anchor interpolation.
Module 2: Master Room & Seat Orchestrator Component: InterviewRoomController.cs
Manages camera seat positioning, zero-clip head culling routines, interview clock timers, candidate profile synchronization, and overall scene lighting state.
Module 3: Real-Time Telepresence & WebSockets Component: Program.cs (ASP.NET Core Kestrel)
High-performance asynchronous WebSocket broker. Handles room concurrency, participant join/leave routing, JSON payload broadcast, and diagnostic health REST endpoints.
Module 4: In-Situ Spatial HUD & Evaluation Rubric Component: VRSpatialVirtualScreen.cs & interview-app.js
Renders 3D floating presentation screens, interactive 5-star scoring rubrics, quick-tag evaluation pills, and auto-saving recruiter notes.

Subsystem Inter-Communication Dataflow

Communication between modules follows a deterministic reactive pattern:

  • Sensor-to-Rig: Hardware sends raw tracking poses at 90Hz to Module 1, which computes calibrated local coordinates.
  • Rig-to-Network: Module 1 passes serialized transforms to Module 3 at 30Hz to conserve network bandwidth while utilizing local predictive extrapolation.
  • Network-to-Scene: Module 3 broadcasts transforms to remote peers, triggering avatar head updates in Module 2.
  • Evaluation-to-Storage: User interactions on the 3D HUD in Module 4 fire event payloads to Module 3, persisting evaluation scorecards into the recruitment database.
Decoupled Threading Architecture: The Unity client leverages C# Job Systems and asynchronous WebSockets, ensuring network latency spikes never stall the 90Hz rendering thread, thus completely preventing visual frame drops.

4.1 Master Interview Room Controller (Unity C# - InterviewRoomController.cs)

The central orchestrator in the Unity engine is InterviewRoomController.cs. It manages seat perspective switching, zero-clip head culling, timer progression, and rubric evaluation. Key implementation excerpts are reproduced below: 

namespace InterviewRoom {
    public enum InterviewRole { Interviewer = 0, Candidate = 1 }
    public enum CameraViewMode { Overview = 0, InterviewerView = 1, CandidateARView = 2, VRGogglesMode = 5 }

    [ExecuteAlways]
    public class InterviewRoomController : MonoBehaviour {
        [Header("Role Selection & Perspective")]
        public InterviewRole activeRole = InterviewRole.Interviewer;
        public float interviewTimer = 0f;
        public bool isTimerRunning = true;

        [Header("Candidate Profile Dossier")]
        public string candidateName = "Alex Mercer";
        public string candidateRole = "Senior Spatial Systems Engineer";
        public int candidateMatchScore = 94;

        [Header("Camera Rig Anchors (1.3m Eye-to-Eye Separation)")]
        public Transform interviewerEyePoint; // Pos: (0, 1.22, 0.65), Yaw: 180 deg
        public Transform candidateEyePoint;   // Pos: (0, 1.22, -0.65), Yaw: 0 deg
        public Camera mainCamera;

        private void Update() {
            if (isTimerRunning) interviewTimer += Time.deltaTime;
            HandlePerspectiveInput();
            UpdateCameraTransform();
            EnforceZeroClipHeadCulling();
        }

        public void SwitchRole(InterviewRole newRole) {
            activeRole = newRole;
            if (activeRole == InterviewRole.Interviewer) {
                targetCamPos = interviewerEyePoint.position;
                targetCamRot = Quaternion.Euler(0f, 180f, 0f); // Look toward -Z
            } else {
                targetCamPos = candidateEyePoint.position;
                targetCamRot = Quaternion.Euler(0f, 0f, 0f);   // Look toward +Z
            }
        }

        // HEAD CULLING: Suppress local user head meshes to eliminate near-clipping
        private void EnforceZeroClipHeadCulling() {
            bool isInterviewer = (activeRole == InterviewRole.Interviewer);
            if (interviewerAvatar != null)
                interviewerAvatar.headRenderer.enabled = !isInterviewer;
            if (candidateAvatar != null)
                candidateAvatar.headRenderer.enabled = isInterviewer;
        }
    }
}

Algorithmic Rationale

The EnforceZeroClipHeadCulling() method guarantees that when a user sits in the Interviewer chair, their own local head and suit collar renderers are suppressed from the main camera's culling mask, completely preventing near-plane polygon clipping while ensuring the candidate avatar across the table remains fully visible.

4.2 6-DoF VR Goggles Rig & Seat Anchor Switching (Unity C# - VRGogglesRig.cs)

The VRGogglesRig.cs module acts as the physical hardware interface. It checks for connected OpenXR devices (Meta Quest, HTC Vive) and provides smooth fallback mouse/keyboard navigation when run on standard desktop workstations: 

namespace InterviewRoom.VR {
    public class VRGogglesRig : MonoBehaviour {
        public enum VRRigSeat { CandidateChair = 0, InterviewerChair = 1, FreeRoam = 2 }

        public Camera vrCamera;
        public Transform leftController, rightController;
        public VRControllerPointer rightPointer;
        public bool isVRHardwareActive = false;
        public float mouseSensitivity = 2.0f;

        private void Awake() {
            CheckVRHardwarePresence();
        }

        private void CheckVRHardwarePresence() {
            // Query Unity XR subsystem for active 6-DoF Head Mounted Display
            List<XRInputDevice> displays = new List<XRInputDevice>();
            InputDevices.GetDevicesWithCharacteristics(
                InputDeviceCharacteristics.HeadMounted, displays);
            isVRHardwareActive = (displays.Count > 0 && XRSettings.isDeviceActive);
            Debug.Log($"[VR Rig] Hardware Active: {isVRHardwareActive}");
        }

        public void SetVRViewMode(VRRigSeat seat) {
            Transform anchor = (seat == VRRigSeat.CandidateChair) 
                ? candidateSeatPoint : interviewerSeatPoint;
            
            if (anchor != null) {
                transform.position = anchor.position;
                transform.rotation = anchor.rotation;
                RecenterVRTrackingSpace();
            }
        }

        private void Update() {
            if (!isVRHardwareActive) {
                SimulateDesktop6DoFLook(); // Mouse Look & WASD Fallback
            }
        }

        private void SimulateDesktop6DoFLook() {
            if (Input.GetMouseButton(1)) { // Right Click Drag to Orbit
                float mouseX = Input.GetAxis("Mouse X") * mouseSensitivity;
                float mouseY = Input.GetAxis("Mouse Y") * mouseSensitivity;
                simYaw += mouseX;
                simPitch = Mathf.Clamp(simPitch - mouseY, -80f, 80f);
                vrCamera.transform.localRotation = Quaternion.Euler(simPitch, simYaw, 0f);
            }
        }
    }
}

using System.Net.WebSockets;
using System.Text.Json;
using System.Collections.Concurrent;

var builder = WebApplication.CreateBuilder(args);
builder.WebHost.UseUrls("http://0.0.0.0:5000", "http://localhost:5000");

var app = builder.Build();
app.UseDefaultFiles();
app.UseStaticFiles();
app.UseWebSockets(new WebSocketOptions { KeepAliveInterval = TimeSpan.FromSeconds(20) });

// High-Concurrency Room Session Manager
var roomSessions = new ConcurrentDictionary<string, InterviewSessionRoom>();

app.Map("/ws/interview", async context => {
    if (context.WebSockets.IsWebSocketRequest) {
        string roomId = context.Request.Query["room"].FirstOrDefault() ?? "interview-room-1";
        string role = context.Request.Query["role"].FirstOrDefault() ?? "interviewer";
        string participantId = Guid.NewGuid().ToString("N")[..8];

        using var webSocket = await context.WebSockets.AcceptWebSocketAsync();
        var room = roomSessions.GetOrAdd(roomId, id => new InterviewSessionRoom(id));
        var participant = new Participant(participantId, role, webSocket);
        
        await room.JoinAsync(participant);
    } else {
        context.Response.StatusCode = StatusCodes.Status400BadRequest;
    }
});

// REST Health & Telemetry Metrics Endpoint
app.MapGet("/api/status", () => Results.Json(new {
    status = "online",
    platform = "WebXR Spatial Interview Telepresence Platform",
    totalActiveRooms = roomSessions.Count,
    activeRoomKeys = roomSessions.Keys
}));

app.Run();

// Asynchronous Broadcast Routine inside InterviewSessionRoom
public async Task BroadcastToPeersAsync(string senderId, string jsonMessage) {
    var bytes = System.Text.Encoding.UTF8.GetBytes(jsonMessage);
    var segment = new ArraySegment<byte>(bytes);
    foreach (var p in _participants.Values) {
        if (p.Id != senderId && p.Socket.State == WebSocketState.Open) {
            await p.Socket.SendAsync(segment, WebSocketMessageType.Text, true, CancellationToken.None);
        }
    }
}
